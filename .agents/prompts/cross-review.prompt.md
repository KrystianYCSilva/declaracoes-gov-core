---
name: cross-review
description: |
  Review code or plans generated by another LLM for errors, hallucinations, and deviations.
  Use when: comparing outputs between CLIs, or reviewing AI-generated code before committing.
---

This code/plan was generated by another AI assistant. Review it critically:

1. **Erros factuais** — APIs that don't exist, wrong method signatures, fabricated classes
2. **Hallucinations** — URLs that don't exist, invented library features, made-up patterns
3. **Desvios de padrão** — Violations of project conventions (naming, structure, architecture)
4. **Over-engineering** — Unnecessary abstractions, design patterns without justification (YAGNI)
5. **Gaps** — Missing error handling, edge cases, validation, null checks

Output format:
```
## Cross-Review: [file/component]

### 🔴 Erros (must fix)
- [list with line references]

### 🟡 Suspeitos (verify)
- [list with what to check]

### 🟢 Correto
- [brief confirmation of what's good]

### Veredicto: [APROVAR / CORRIGIR / REJEITAR]
```

Do NOT rewrite the code. Only identify problems. Let the user decide how to fix.
