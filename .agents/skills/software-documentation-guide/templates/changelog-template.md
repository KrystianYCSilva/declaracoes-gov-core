## Entry Format Guide

Each entry should:
1. Start with a verb (Add, Change, Fix, Remove, Deprecate)
2. Describe the user-visible change (not internal refactoring)
3. Reference the issue or PR number
4. Be specific — avoid "various improvements"

### Categories
- **Added**: New features
- **Changed**: Changes in existing functionality
- **Deprecated**: Soon-to-be removed features
- **Removed**: Removed features
- **Fixed**: Bug fixes
- **Security**: Vulnerability fixes
