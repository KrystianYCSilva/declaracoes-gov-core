# Sources

Authoritative references for requirements engineering methodology, standards, and traceability.

## IEEE / ISO Standards

- IEEE 29148:2018 Systems and Software Engineering — Life Cycle Processes — Requirements Engineering:
  `https://www.iso.org/standard/72089.html`
- IEEE 830-1998 Recommended Practice for Software Requirements Specifications (legacy but widely referenced):
  `https://standards.ieee.org/ieee/830/1222/`
- ISO/IEC/IEEE 15288 Systems and Software Engineering — System Life Cycle Processes:
  `https://www.iso.org/standard/63711.html`

## Business Analysis

- IIBA BABOK Guide (Business Analysis Body of Knowledge):
  `https://www.iiba.org/standards-and-resources/babok/`
- IIBA Agile Extension to the BABOK Guide:
  `https://www.iiba.org/standards-and-resources/agile-extension/`

## Software Engineering Body of Knowledge

- SWEBOK V4 — Chapter 1: Software Requirements:
  `https://www.computer.org/education/bodies-of-knowledge/software-engineering/v4`

## Agile Requirements

- User Story Mapping (Jeff Patton):
  `https://jpattonassociates.com/user-story-mapping/`
- BDD / Given-When-Then (Cucumber documentation):
  `https://cucumber.io/docs/gherkin/reference/`
- Specification by Example (Gojko Adzic):
  `https://gojko.net/books/specification-by-example/`

## Traceability Tools Reference

- NASA Systems Engineering Handbook on traceability:
  `https://www.nasa.gov/reference/nasa-systems-engineering-handbook/`

## Usage Notes

- Use IEEE 29148 when the project needs a formal requirements specification structure.
- Use BABOK when the focus is business analysis and stakeholder elicitation.
- Use BDD/Gherkin when acceptance criteria need to drive automated test generation.
- These are methodology anchors; adapt them to team size, delivery mode, and regulatory context.
